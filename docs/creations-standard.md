# תקן "יצירות": כל אפליקציה מפיקה כתבות ויצירות מהידע שלה

ענת, 03.11.2026: "כל אפליקציה צריכה שיהיה לך דף עם כתבות שהיא יכולה להפיק מנושאים שונים שעולים מהידע, הבנה ויישום. היצירות של האפליקציה."
כל נושא הוא **חדר**. בכל חדר יש כמה יצירות בעיצובים שונים, וכל יצירה ראויה לעמוד בפני עצמה במיצג.
כל יצירה עולה לחדר משלה ב-TAARUCHA, ויורדת להדפסה בגודל A4.

## כתבות (גרסה 2, 07.11.2026)
ענת: "להכין כתבות, יפות פוטוגניות, אך תרכז כל כתבה ב-A4 אחד. צור כפתור ליצירת כתבה באותו הפורמט לכל אפליקציה, פורמט משלה בהתאם לרוח הדברים שלה. וכפתור להורדה והדפסה. ולכל אפליקציה תאפשר לעלות את הכתבה שנוצרה ישר לתוך החדר שלה במוזאון."
- **כתבה = עמוד A4 אחד לכל נושא.** היא מורכבת אוטומטית מהיצירות של הנושא, לפי תפקיד:
  - **תמונה ראשית:** היצירה הראשונה עם תמונה (poster, veil, post, essay), עם הקרדיט שלה.
  - **כותרת עליונה:** השלב ושם האפליקציה. **כותרת:** `topic.title`. **פתיח:** `topic.sub`.
  - **ציטוט מוגדל:** יצירת `quote`, במירכאות, עם מי ומקור.
  - **תובנה במרקר:** יצירת `insight` (ואם אין, `gradient`).
  - **ממה למה:** יצירת `fromto`. **גוף:** `essay.body`, ואם אין, שורות ה-`post`. **הייקו:** יצירת `haiku`.
  - **תחתית:** שם האפליקציה, "אד' ענת שטיבלמן A&I" והכתובת.
- **אין טקסט חדש בכתבה.** כל מילה מגיעה מהיצירות, וטקסט שחוזר פעמיים מוצג פעם אחת. מספרים מודגשים אוטומטית.
- **התאמה לעמוד:** כל הטקסט גדל או קטן יחד (עד 0.7). אם עדיין גולש, יורדים גושים שלמים, לפי הסדר: הייקו, ממה למה, הפסקאות האחרונות. גוש אף פעם לא נחתך באמצע. הגלישה נמדדת גאומטרית, והתוצאה בשדה `data-fit` של הגיליון (`over` = גלישה).
- **הדף** (`<app-creations>`): שורות מה, איך ומה יוצא, סינון לפי שלב, וכפתור "יצירת כתבה". אחר כך כל הכתבות בדף אחד, לפי שלב, שלוש בשורה במחשב ואחת בטלפון.
  - **מתחת לכל כתבה, שלושה כפתורים באותו גודל:** "הורדה והדפסה" (עמוד A4 אחד, ושם הקובץ הוא כותרת הכתבה), "העלאה לחדר במוזיאון", "הגדלה".
  - **"היצירות הבודדות (N)":** נפתח בשקט, ובו תשע היצירות של הנושא, כמו קודם.
- **"יצירת כתבה":** פאנל בתוך הדף. מימין הכתבה החיה, ומשמאל רשימת המקורות מ-`pool`, לפי שלב, עם חיפוש (איקס אפור לניקוי) ו"הפתעה". בלי `pool`, הנושאים הם המאגר.

- `app.article.css` (לא חובה): CSS לכוונון עדין. הוא מוזרק רק לכתבות של האפליקציה (`[data-ar-app="<app.id>"]`).
- הצבעים באים מ-`app.palette`. לבדיקה: `layout="<שם>"` על הרכיב, או `?ar-layout=<שם>` בכתובת.

### מאגר המקורות (`pool`)
מערך באותו מבנה כמו נושא: `id`, `zone`, `title`, `sub`, `creations[]` (4 עד 6 יצירות, רק מהנתונים). מזהה הכתבה: `pool:<id>`.

### כתבה לבדה: `<app-article>`
```html
<app-article src="https://<app>/creations.json" topic="<id>"></app-article>
<app-article src="https://<app>/creations.json" pool="<id>"></app-article>
```
- טוען את הקובץ (פעם אחת לכל כתובת), מחיל צבעים ופורמט, ומתאים את הכתבה לרוחב שלו. `layout` לא חובה.
- כשמוכן: `data-ready="1"` ואירוע `ar-ready`. כשנכשל: אירוע `ar-error`.

### המוזיאון: חדר לכל אפליקציה
- **הכפתור "העלאה לחדר במוזיאון"** פותח: `https://taarucha.vercel.app/studio/import?article=1&src=<כתובת מלאה של creations.json, מקודדת>&topic=<id>` (או `&pool=<id>`).
- **ב-TAARUCHA:** הכתבה מוצגת בגדול, ואחרי "תלייה בחדר של <האפליקציה>" נוצר או מתעדכן החדר `room-<app.id>` (תערוכה קבועה).
- **העבודה בחדר:** `layout: 'cr-article'`, ו-`body` הוא JSON: `{"src": "...", "topic": "..."}` או `{"src": "...", "pool": "..."}`. הקיר מציג את הכתבה החיה דרך `<app-article>`. העלאה חוזרת של אותה כתבה מעדכנת אותה ולא מכפילה.
- `app.description` (לא חובה) הוא הטקסט האוצרותי של החדר.

## תשעת העיצובים (`style`)
| style | שם | שדות |
|---|---|---|
| `poster` | טקסט על תמונה | title, text, image, pos |
| `gradient` | שדה צבע (גרדיינט מצבעי ה-DNA) | title, text |
| `veil` | שקיפות: זכוכית חלבית על תמונה | title, text, image |
| `insight` | תובנה: שורה גדולה, הסבר עם פס מרקר | title, text |
| `quote` | ציטוט מוגדל | quote, who, cite |
| `haiku` | הייקו בשלוש שורות מדורגות, וחותם | lines[3], text |
| `post` | פוסט מוכן לרשת | title, text (שורות ב-\n), image, tags[] |
| `fromto` | פרשנות ממה למה | title, from, to, fromLabel, toLabel, text |
| `essay` | מאמר בשתי עמודות | title, text (פתיח), image, body[] |

**שדות לכל יצירה:**
- `id`, `style`.
- `kicker`: מופיע בתחתית היצירה.
- `credit`: קרדיט לתמונה.
- `png`: נכתב אוטומטית בייצוא.

**סימון בטקסט:** `**מודגש**` לבולד, ו-`==מרקר==` להדגשה במרקר צהוב.

## creations.json
```json
{
  "app": { "id": "amirot", "name": "אמירות", "url": "https://amirot-gh.vercel.app", "repo": "Anat1969/Amirot-GH",
           "description": "…", "article": { "layout": "daf" },
           "palette": { "a": "#1f3a68", "b": "#a3261e", "c": "#b8700f", "s": "#1d7a4f", "accent": "#1d7a4f", "paper": "#fff" } },
  "topics": [
    { "id": "haste", "zone": "הבנה", "title": "למהר או לחכות", "sub": "…", "room": "amirot-haste",
      "creations": [ { "id": "1", "style": "poster", "title": "…", "text": "…", "image": "art/haste-a.jpg" } ] }
  ],
  "pool": [ { "id": "…", "zone": "ידע", "title": "…", "sub": "…", "creations": [ … ] } ]
}
```
**נתיבים ושדות:**
- נתיב תמונה יחסי מתפרש ביחס לקובץ ה-JSON.
- `room` הוא ה-slug של החדר ב-TAARUCHA. כשהוא קיים, הכפתור "כניסה לחדר" פעיל.
- `palette` הוא מפתחות ה-DNA של האפליקציה:
  - `a`, `b`, `c`, `s`: צבעים.
  - `accent`: צבע הדגשה.
  - `marker`: צבע המרקר.
  - `paper` ו-`paper2`: צבעי הרקע.
  - `ink`: צבע הטקסט.
  - `b-wash` ו-`s-wash`: גוונים בהירים לרקע.

## כללי תוכן (רמה 999)
- **שלושה שלבים:**
  - **ידע:** עובדה עם מקור.
  - **הבנה:** מנגנון, השוואה או "ממה למה".
  - **יישום:** מה עושים מחר בבוקר, ודוגמה מהעיר.
- **כמה חדרים:** 6 לפחות לכל אפליקציה, ולפחות אחד מכל שלב.
- **כמה יצירות:** בכל חדר 4 עד 6 יצירות, בעיצובים שונים. אף עיצוב לא חוזר באותו חדר.
- **כמה כותרת:** כותרת עד 8 מילים. הסבר עד 20 מילים. מאמר: 3 עד 5 פסקאות קצרות.
- **מקורות:** רק עובדות שכבר נמצאות בנתונים של האפליקציה. לא ממציאים, ולכל ציטוט יש מקור.
- **תמונות:** רק תמונות שכבר יש לאפליקציה רישיון עליהן. כשאין תמונה, בוחרים עיצוב בלי תמונה.
